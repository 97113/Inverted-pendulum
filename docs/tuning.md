# 制御ゲインの調整手順

制御則は状態フィードバックです（`src/balance.cpp`）。

```
u = Kθ·(θ − θtrim) + Kθd·θ̇ − Kx·(x − x_ref) − Kv·(v − v_ref)
```

| 記号 | 意味 | `config.h` | 単位 |
| --- | --- | --- | --- |
| Kθ  | 姿勢角 | `kGainPitch` | N·m / rad |
| Kθd | 姿勢角速度 | `kGainPitchRate` | N·m / (rad/s) |
| Kx  | 走行位置 | `kGainPos` | N·m / m |
| Kv  | 走行速度 | `kGainVel` | N·m / (m/s) |
| Kψ  | ヨーレート | `kGainYawRate` | N·m / (rad/s) |

`u` は左右共通の車輪トルクで、旋回はこれに差分トルクを重ねます。

---

## 事前準備

- `docs/hardware.md` の初回通電チェックリストを全部通しておくこと
- `kTorqueLimit` を小さめ（2.0 N·m 程度）にしておく
- **最初は必ず機体に紐を付けるか、転倒しても壊れない場所で行う**

---

## 手順 1 : 姿勢だけ立たせる

```c
kGainPos = 0.0f;
kGainVel = 0.0f;
kTrimIntegralGain = 0.0f;
```

この状態では「その場で立つが、じわじわ流れていく」のが正解です。

1. `kGainPitch` を小さい値（例 5.0）から始め、手で支えながら ARM する
2. 支えを緩めて、倒れる側に車輪が動くことを確認する
   - **動きが逆なら制御が発散するので即 DISARM**。
     `kAccelPitchNumSign` / `kGyroPitchSign`、または `kMotorDirLeft/Right` の符号を見直す
3. 倒れるのを止めきれないなら `kGainPitch` を 1.2 倍ずつ上げる
4. 小刻みに振動しはじめたら上げすぎ。そこから 2 割ほど下げる
5. 振動が残る場合は `kGainPitchRate` を 0.1 ずつ上げて減衰させる
   - `kGainPitchRate` を上げすぎると高周波でカタカタ鳴る。鳴ったら下げる

目安として、`kGainPitchRate` は `kGainPitch` の 5〜10 % 程度に落ち着きます。

## 手順 2 : 流れを止める

```c
kGainVel = 1.0f;   // ここから開始
```

1. `kGainVel` を上げていくと、前後に流れる速度が落ちてくる
2. 上げすぎるとゆっくりした前後の揺れ（周期 1〜2 秒）が出る。出たら下げる
3. 次に `kGainPos` を 0.5 ずつ上げると、定位置に戻ろうとするようになる
4. `kGainPos` も上げすぎると低周波の揺れになる

## 手順 3 : 重心オフセットの自動補正

```c
kTrimIntegralGain = 0.02f;
```

バッテリやモータの位置で重心が前後にずれていると、手順 2 までだと
一定方向にじわじわ流れ続けます。これを吸収するのが trim 積分です。

- 画面の `trim` が数秒かけて一定値に落ち着けば正常
- `trim` が `kTrimLimit`（既定 ±0.10 rad ≒ ±5.7°）に張り付く場合は、
  **ゲインではなく機体の重心を直す**べきです。Core2 やバッテリの位置をずらしてください
- 落ち着くのが遅すぎるなら `kTrimIntegralGain` を上げ、
  ふらつくなら下げます

## 手順 4 : 操縦感

| パラメータ | 調整内容 |
| --- | --- |
| `kMaxSpeed` | 前後の最大速度。まず 0.5 m/s 程度から |
| `kMaxYawRate` | 旋回の最大速度 |
| `kCommandSlewPerSec` | 小さくすると指令が滑らかになり、急発進で転びにくくなる |
| `kStickDeadzone` | スティックの中立遊び |
| `kGainYawRate` | 旋回の効き。振動するなら下げる |

既定ではスティックの効きは最大値の 50 % に抑えられていて、
**RB を押している間だけフルスケール**になります（`src/main.cpp` の `btnBoost`）。

## 症状別の対処

| 症状 | 原因の候補 |
| --- | --- |
| ARM 直後に一気に倒れる | 姿勢角かモータ方向の符号が逆 |
| 高周波でカタカタ振動 | `kGainPitch` / `kGainPitchRate` が高すぎる |
| 周期 1〜2 秒の前後揺れ | `kGainVel` / `kGainPos` が高すぎる |
| 一定方向に流れ続ける | `kTrimIntegralGain` が 0、または重心が大きくずれている |
| 立つが方向がじわじわ回る | `kGyroYawSign` の符号、または左右の車輪径・摩擦の差 |
| 画面の `overrun` が増える | 制御周期に間に合っていない。`kControlHz` を下げる |
| `CAN` が `OFF` になる | 終端抵抗、配線、ボーレート（1 Mbps）を確認 |
| 倒れる速さに車輪が追いつかない | 母線電圧が低いと最高回転数が落ちる。`VBUS` を確認し、電池の直列数を見直す |

## 速度モードを使う場合

`config.h` の `kMotorMode` を `MotorMode::Speed` にすると、
モータ側の速度制御に指令を渡す構成になります（制御出力を車輪の角加速度とみなして積分）。

- トルクモードとは**次元が違うため、ゲインは全部やり直し**になります
- モータによっては、パラメータ書き込みに対してフィードバックフレームを返さず、
  画面上でモータが `--` のままになることがあります。その場合はトルクモードを使ってください
- 倒立振子としてはトルクモードのほうが素直です。速度モードは
  トルクモードでどうしても詰められないときの代替と考えてください
