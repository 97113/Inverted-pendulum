01

PC の環境構築

各 PC で 1 回だけ。所要 30〜60 分（初回ビルドのダウンロード込み）

  1. Git for Windows を入れる

    git-scm.com からインストーラを取得。途中の選択肢は既定のままで構いません。改行コードは既定の「Checkout Windows-style, commit Unix-style」を選びます。

    インストール後、PowerShell で名前とメールを登録します（コミットに残る作者名です）。

    GitHub へのログインは、初回の push 時にブラウザが開いて行われます（Git Credential Manager が同梱）。

  2. VS Code と PlatformIO IDE 拡張を入れる

    VS Code をインストールし、拡張機能（Ctrl+Shift+X）で PlatformIO IDE を検索して入れます。初回は PlatformIO Core（Python 込み）の自動セットアップに数分かかります。完了すると左端にアリの頭のアイコンが出ます。

    Python を別途入れる必要はありません。PlatformIO が専用の Python を %USERPROFILE%\.platformio\penv に持っており、後述のロガーもそれを使います。

  3. Core2 の USB ドライバを確認する

    Core2 を USB-C で繋ぎ、デバイスマネージャーの「ポート (COM と LPT)」を開きます。製造時期で USB シリアル変換チップが違います。

    表示名チップ対処
    Silicon Labs CP210x USB to UART Bridge (COMx)CP2104（初期ロット）表示されなければ Silicon Labs の CP210x VCP ドライバを入れる
    USB-Enhanced-SERIAL CH9102 / CH343 (COMx)CH9102F（以降のロット）表示されなければ WCH の CH343/CH9102 ドライバを入れる
    「ほかのデバイス」に黄色い ! が出るどちらかドライバ未導入。上のどちらかを入れて挿し直す

    表示された COM 番号を、上の作業者プロファイルに入れてください。

    何も出ない場合は、充電専用の USB ケーブルを疑います。データ通信対応のケーブルに替えてください。

  4. リポジトリを clone して VS Code で開く

    作業フォルダはパスに日本語やスペースを含まない場所にします（ツールチェーンが失敗することがあります）。

    VS Code で開くと PlatformIO が platformio.ini を認識し、ESP32 のツールチェーンとライブラリ（M5Unified、Xbox コントローラ用）を自動で取得します。

  5. 初回ビルドを通す

    VS Code 下部のステータスバーの ✓（Build） を押すか、PlatformIO のターミナルで実行します。

    最後に [SUCCESS] が出れば環境構築は完了です。

    pio が見つからないと言われたら通常の PowerShell には pio のパスが通っていません。VS Code 左の PlatformIO アイコン → Quick Access › Miscellaneous › New Terminal で開いたターミナルを使ってください。
  6. （モータ設定担当のみ）RobStride の PC ツールを用意する

    モータの CAN ID 変更や単体の動作確認に使います。メーカー配布の PC 用ソフト（上位機ソフト）と、それに対応した USB-CAN アダプタが必要です。ソフト名と入手先は製品に付属の資料で確認してください。全員が入れる必要はなく、モータを設定する人の PC だけで構いません。

02

チームでの運用

コードは GitHub で、実機は予約と引き継ぎで共有します

ブランチのルール

ブランチ用途決まりごと
mainいつでも書き込んで動く版直接 push しない。Pull Request でレビューしてから merge
feature/tanaka-pitch-gain機能追加・修正・ゲイン調整1 テーマ 1 ブランチ。作業者名を含める

1 日の流れ

  1. 最新の main から作業ブランチを作る
  2. 小さく区切ってコミットする

    コミットメッセージには「何を変えたか」と、ゲイン変更なら「実機でどうだったか」を書きます。後から別の人が読んで追える記録になります。

  3. push して Pull Request を作る

    GitHub の画面で Pull Request を作り、本文に「どの機体で検証したか」「ログのファイル名」を書きます。もう 1 人が確認してから merge します。

config.h の衝突に注意調整パラメータはすべて include/config.h に集まっているため、複数人が同時にゲインを触ると必ず衝突します。ゲイン調整は「今は誰が担当か」を決めて 1 人ずつ行い、終わったら早めに merge してください。

共有機実機を交代で使うときの決まり

  1. 使う前に予約する

    チームの予約表（共有カレンダーや GitHub Issue など、チームで 1 か所に決める）に、機体 ID・時間帯・作業テーマを書きます。

  2. 書き込んだ版を記録する

    今のファームは画面にバージョンを出さないため、書き込んだ人がコミットを記録しておかないと、次の人は何が入っているか分かりません。書き込みの直後に次を実行し、出てきた値を予約表に残します。

    git status に何か出る場合は、コミットしていない変更を書き込んでいます。その旨も記録してください。

  3. 返すときは main の版に戻す

    次の人が「いつもの動き」から始められるよう、使い終わったら main を書き込んで返します。

    DISARM してからバッテリを外し、バッテリ電圧と気づいた不具合を予約表に書いて終了です。

個人機自分の機体の設定差分を管理する

機体ごとに CAN Unit を挿すポート、モータの向き、車輪径、IMU の向きが違うことがあります。これらは config.h の値ですが、自分の機体の値をそのまま main に入れると、ほかの人の機体が動かなくなります。

  • 自分の機体固有の値は、リポジトリの docs/ に機体ごとのメモ（例 docs/robots/R1.md）として残す
  • 作業ブランチでは書き換えてよいが、Pull Request の前に共通値へ戻すか、差分が意図したものかレビューで確認する
  • 恒久的な対策は今後の改善案の「機体ごとのビルド設定」を参照

🗑クリーンpio run -t clean

書込みの手順

  1. 機体を安全な状態にする

    書込み中と再起動直後はモータへの指令が途切れます。車輪を浮かせるか、モータの電源（バッテリ）を外してから書き込みます。

  2. COM ポートを確認する

    複数の機器を繋いでいると、PlatformIO の自動選択が別の COM を選ぶことがあります。ポートは明示するのが確実です。

  3. 書き込む

    シリアルモニタやロガーがポートを開いたままだと失敗します。先に閉じてください（モニタは Ctrl+C）。

  4. 起動を確認する

    Core2 が再起動し、画面が CALIBRATING → DISARMED に進めば成功です。較正の約 2 秒間は機体を動かさないでください。

04

モータの操作

目的によって経路が 2 つあります。同時には使いません

A. PC ツールから直接

PC → USB-CAN アダプタ → モータ

  • CAN ID の変更（出荷時は 2 台とも 127）
  • ボーレート 1 Mbps の確認
  • 1 台ずつの回転確認、故障ビットや温度の読み出し

新しいモータを入れたとき、交換したとき、故障を切り分けるときに使います。

B. Core2 のファームから

Xbox コントローラ / 本体ボタン → Core2 → CAN Unit → モータ

  • ARM / DISARM、倒立制御、走行と旋回
  • 普段の検証はすべてこちら
2 つの経路を同時に繋がないUSB-CAN アダプタを使うときは Core2 の電源を切るか、CAN Unit の Grove ケーブルを抜いてください。Core2 は起動時と動作中にモータへ指令を送り続けるため、PC ツールの操作と混ざって予期しない動きになります。

A. 初期設定（モータを入れたら最初に 1 回）

  1. モータを 1 台だけ USB-CAN に繋ぐ

    2 台とも ID 127 のままだと区別できないため、必ず 1 台ずつ設定します。車輪は外すか浮かせておきます。

  2. CAN ID を書き込む

    左を 1、右を 2 にします（config.h の kMotorIdLeft / kMotorIdRight と一致させる）。ボーレートが 1 Mbps であることも確認します。モータ本体に ID のラベルを貼っておくと後で迷いません。

  3. 低速で回して確認する

    PC ツールの速度モードなどで、ゆっくり正転・逆転することを確認します。故障ビットが立っていないこと、温度が読めることも見ます。

  4. 終端抵抗を設定して機体に戻す

    バスの末端になるモータだけ終端を ON、途中のモータは OFF。CAN Unit 側には付属の 120 Ω を付けます。

B. ファームからの操作

操作動作
コントローラ A / 本体 BtnAARM（起立開始）。±5° 以内でないと受け付けない
コントローラ B / 本体 BtnBDISARM（モータ停止）
本体 BtnCジャイロ再較正と走行距離のリセット
左スティック上下 / 右スティック左右前進・後退 / 旋回
RB 押しっぱなし速度リミッタ解除（通常は最大値の 50 %）

転倒（35° 超）、CAN の途絶やバスオフ、モータの故障ビットで自動停止します。母線電圧が 13.0 V 未満だと ARM を拒否します。

07
トラブル対処
症状で絞り込めます

  
  
  

    
デバイスマネージャーに COM ポートが出ないPC
USB ケーブルが充電専用の可能性が高いです。データ通信対応のケーブルに替えてください。それでも出ない場合は 01 の 3 のドライバを入れます。

    
書込みで「Access is denied」「could not open port」書込み
ほかのアプリがポートを開いています。シリアルモニタ、ロガー、別の VS Code ウィンドウ、Arduino IDE などを閉じてください。Windows では COM ポートを同時に開けるのは 1 つのアプリだけです。

    
書込みが途中で止まる、「Failed to connect to ESP32」書込み
ケーブルや USB ハブで速度が出ていない可能性があります。PC 本体の USB 端子に直接挿し、platformio.ini の upload_speed を 1500000 から 921600 に下げて試します（下げた場合は自分のブランチだけにとどめ、main には入れない）。

    
pio コマンドが見つからないPC
PlatformIO のターミナル（Quick Access › New Terminal）から実行してください。通常の PowerShell には PATH が通っていません。

    
ビルドがパス関係のエラーで失敗するビルド
リポジトリを日本語やスペースを含むフォルダ（OneDrive 配下のデスクトップなど）に置いていないか確認します。C:\dev のような短いパスに clone し直すと解決することが多いです。

    
git pull で config.h が衝突したGit
VS Code のソース管理画面で衝突箇所を開き、「現在の変更」「入力側の変更」のどちらを残すか選びます。ゲイン値の衝突は、その値で実機検証した人に確認してから決めてください。

    
画面の CAN が OFF のままCAN
CAN Unit のポートと kCanTxPin / kCanRxPin の一致、CAN_H / CAN_L の配線、両端の 120 Ω 終端を確認します。04 のポート設定で値を作り直せます。

    
モータ表示が -- のままCAN
モータの CAN ID が 1 と 2 になっているか（出荷時は 127）、ボーレートが 1 Mbps か確認します。PC ツールで 1 台ずつ確認してください。

    
ロガーを起動したら Core2 が再起動したロギング
COM ポートを開くと ESP32 の自動リセット回路が働くことがあります。必ず DISARMED の状態でロガーを起動してから ARM してください。

    
ロガーの CSV が空ロギング
ファームに「T,」行を出力するコードが入っていないか、ボーレートが一致していません。05 の 3 のコードを入れて書き込み直し、シリアルモニタで T,... が流れていることを先に確認します。

    
コントローラが繋がらない（PAD が OK にならない）操縦
Xbox コントローラのペアリングボタンを長押しします。ほかの PC やスマートフォンと繋がっていると取られるので、そちらの Bluetooth を切ります。共有機で複数のコントローラがある場合は kGamepadAddress に MAC アドレスを書いて固定できます。

    
ARM 直後に一気に倒れる制御
姿勢角かモータ方向の符号が逆です。06 の台上チェックの 6 と 7 をやり直してください。

    
高周波でカタカタ振動する制御
kGainPitch か kGainPitchRate が高すぎます。2 割ほど下げます。

    
周期 1〜2 秒で前後に揺れる制御
kGainVel か kGainPos が高すぎます。

    
倒れる速さに車輪が追いつかない電源
母線電圧が低いとモータの最高回転数が落ちます。VBUS を確認し、バッテリの直列数を見直してください（docs/hardware.md の検討表）。

  

  
該当する項目がありません。docs/tuning.md の症状別の表も確認してください。
